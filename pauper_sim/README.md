# Pauper Duel

Сторонний небольшой веб-проект (не связан с Telegram-ботом): симулятор турнирных
матчей в Pauper по винрейтам. Хостится отдельным systemd-сервисом на том же
сервере, что и бот: `http://158.160.9.28:8083`.

## Как это работает

1. Пользователь вводит список игроков построчно: `Имя (Архетип колоды)`.
2. Архетип выбирается/подбирается из **топ-20** колод по числу матчей, распарсенных
   со страницы <https://mtgdecks.net/Pauper/winrates>.
3. Кнопка «Старт» — случайная жеребьёвка: список перемешивается и пары образуются
   **снизу вверх** (последний в перемешанном списке играет с предпоследним и т.д.).
   При нечётном числе один игрок пропускает ход (bye).
4. Для каждой пары кнопка «Сыграть игру» разыгрывает одну партию: победитель
   выбирается случайно с вероятностью, взятой из **попарных винрейтов матчапов**
   (на сайте таблица содержит винрейт каждой колоды против каждой). Если пары в
   таблице нет — используется нормализованный общий винрейт. Матч играется до
   **двух побед** (Bo3), дальше — следующая пара.

Жеребьёвка и «бросок» делаются на сервере (`/api/pair`, `/api/roll`); состояние
турнира хранится в браузере (localStorage).

## Структура

```
pauper_sim/
  app.py        — FastAPI: статический фронтенд + JSON API
  winrates.py   — парсер mtgdecks.net (попарные винрейты) + кэш
  logic.py      — чистая логика: вероятность победы, бросок, жеребьёвка
  static/       — фронтенд (vanilla JS, без сборки)
  tests/        — тесты парсера, логики и API (pytest, без сети)
  data/winrates_snapshot.json — зафиксированный срез данных (фолбэк при недоступности сайта)
```

## API

| Метод | Путь | Описание |
|---|---|---|
| GET | `/` | Фронтенд |
| GET | `/healthz` | Живость |
| GET | `/api/winrates?force=1` | Винрейты (кэш до 6 ч) |
| POST | `/api/winrates/refresh` | Принудительный ре-парсинг |
| POST | `/api/roll` `{a, b}` | Разыграть игру, вернуть `{winner: "a"\|\"b\", probability_pct}` |
| POST | `/api/pair` `{players: [{name, deck}]}` | Жеребьёвка, вернуть `{matches, bye}` |

## Парсинг и доступность mtgdecks.net

mtgdecks отдаёт Cloudflare-челлендж на несвежие сессии. Fetcher сначала «прогревает»
сессию на мета-странице формата и только потом запрашивает винрейты; при неудаче —
cloudscraper. Если живой парсинг недоступен, сервис отдаёт последний успешный
парсинг (файл `pauper_sim/data/winrates_cache.json`, создаётся на сервере) или
бандл-снапшот `winrates_snapshot.json` из репозитория. Кнопка «Обновить данные»
пробует пере-парсить сайт.

## Локальный запуск

```bash
python3 -m venv .venv
.venv/bin/pip install -r pauper_sim/requirements.txt
.venv/bin/uvicorn pauper_sim.app:app --host 0.0.0.0 --port 8083
# http://localhost:8083
```

Тесты:

```bash
.venv/bin/python -m pytest pauper_sim/tests/ -v
```

## Деплой

Деплоится GitHub Actions при пуше в `main` по путям `pauper_sim/**`
(`.github/workflows/pauper_deploy.yml` -> `bot/deploy_pauper_sim.sh`).

Ручной деплой:

```bash
bash bot/deploy_pauper_sim.sh
```

Система: systemd-юнит `pauper-sim.service`, порт `8083` (0.0.0.0), каталог
`/home/mbabaev/MetaTheGathering/pauper_sim`, отдельный venv, своих секретов нет.
