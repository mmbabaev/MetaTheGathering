# Автоматические действия (scheduler)

Все автоматические действия по времени и событиям живут в `bot/scheduler.py`
(`setup_scheduler()`), которая регистрирует джобы в `app.job_queue` PTB. Времена
указаны в таймзоне `settings.TOURNAMENT_TIMEZONE` (по умолчанию из конфига клуба,
обычно Europe/Moscow).

Два типа автоматизации:
- **по времени** — `run_daily` / `run_repeating` (джобы ниже);
- **по событию** — действия, которые срабатывают внутри импорта при изменении
  данных (новые раунды → уведомления; см. раздел «Событийные действия»).

## Расписание клубов — живёт в БД (issue #124/#125)

⚠️ **Расписание — данные, а не код.** Строки лежат в таблице `club_schedules` и правятся
админом из `/schedule`. Правка в коде на прод НЕ влияет: код держит только дефолты для
первичного сида пустой таблицы (`core/clubs.py` → `default_schedules()`, засевается
`ScheduleService.ensure_defaults()` при старте бота).

Турнир создаётся в `create_time`, игра в `game_time`, импорт с AetherHub — в каждое из
`import_times`, напоминание — в `reminder_time`. Выключенная строка (`enabled=false`) не
доходит до планировщика вообще: ни создания, ни напоминания, ни импортов.

Дефолты для сида (актуальное состояние смотри в `/schedule`, а не здесь):

| Клуб | День | create_time | game_time | reminder | import_times |
|------|------|-------------|-----------|----------|--------------|
| 🐠 Goldfish | пятница | 12:00 | 19:45 | 19:45 | 20:00–00:30 каждые 30 мин |
| 🦄 Edinorog | понедельник | 12:00 | 19:30 | 19:25 | 20:00–00:30 каждые 30 мин |
| 🦄 Edinorog | четверг | 12:00 | 19:30 | 19:25 | 20:00–00:30 каждые 30 мин |

Отладочный клуб (`[DEBUG] 🐠`, четверг 12:30, импорт 12:31, `find_latest=True`) добавляется
только при `settings.DEBUG` и через БД **не** управляется — это свойство отладки.

`chat_id`, ссылка на AetherHub и эмодзи клуба — инфраструктура, остаются в коде
(`core/clubs.py` → `club_identities()`), из UI не меняются.

### Что можно править в UI

В карточке строки (`/schedule` → тап по строке):
- **🕐 Создание / 🎮 Игра / 🔔 Напоминание** — ввод времени текстом `ЧЧ:ММ`; для напоминания
  можно прислать «выкл», чтобы отключить (анонс 2 не шлётся).
- **🔄 Импорты** — пресет `начало-конец/шаг`, например `20:00-00:30/30` (каждые 30 мин с 20:00
  до 00:30, окно через полночь поддержано), или «выкл».
- **📆 День недели** — пикер из 7 дней. Смена на день, который у клуба уже занят, отклоняется
  (нарушение уникальности `(club_name, weekday)`).
- **⏸/▶️** — включить/выключить строку целиком.

Добавление и удаление строк расписания через UI пока не делается — только правка существующих.

### Применение правок без рестарта

`reload_schedule_jobs(app)` снимает все джобы с префиксами `create_tournament[`,
`prestart_reminder[`, `aetherhub_import[` и вешает их заново по текущему состоянию БД.
Зовётся из `/schedule` после каждой правки, поэтому изменение действует сразу.
Глобальные джобы (таймер импорта, ночной реимпорт, авто-раскрытие колод) расписанием
не управляются и переживают перезагрузку без изменений.

## Джобы по времени

### 1. Создание турнира — `CreateTournamentJob`
- **Когда:** `run_daily` в `create_time` в нужный день недели (по одной джобе на расписание).
- **Что делает:** закрывает предыдущий активный турнир клуба → создаёт новый в статусе `REGISTRATION` → шлёт анонс с числом записавшихся и **кнопкой-диплинком «📝 Записать колоду»** (`send_registration_open`). Адресаты — **групповой чат клуба** (`club.chat_id`, если задан) и владелец (`OWNER_CHAT_ID`), дедуплицированно. Диплинк `t.me/<bot>?start=deck_<id>` ведёт игрока сразу в запись колоды.
- Название: `<emoji> <Клуб> Pauper <дата>`.

### 1b. Напоминание перед стартом — `PreStartReminderJob`
- **Когда:** `run_daily` в `schedule.reminder_time` в день расписания (Goldfish 19:45, Edinorog 19:25). Регистрируется, только если у расписания задан `reminder_time`.
- **Что делает:** находит активный турнир клуба и шлёт напоминание «турнир начинается — запишите колоду» с той же кнопкой-диплинком (`send_registration_open`). Нет активного турнира — молча пропускает.

### 1c. Обновление числа записавшихся — `RegistrationMessageRefreshJob`
- **Когда:** `run_repeating` каждые 15 секунд.
- **Что делает:** сравнивает реальное число участников с показанным в последних регистрационных сообщениях и редактирует только изменившиеся. Поэтому учитываются Telegram, web, CLI и импорты без специальных callback-хуков. Удалённые или недоступные сообщения отключаются после постоянной Telegram-ошибки; временные ошибки повторяются на следующем цикле.

### 2. Плановый импорт с AetherHub — `AetherhubImportJob`
- **Когда:** `run_daily` в каждое `aetherhub_fetch_time` в день расписания (по джобе на каждое время).
- **Что делает:** находит сегодняшний Pauper-турнир клуба на странице AetherHub клуба (`find_todays_pauper_tournament`) → импортирует (`import_tournament`: участники, паринги, счёт) → сохраняет `aetherhub_url` турнира. При новых раундах — уведомления об оппоненте (см. ниже).

### 3. Поминутный импорт по флагу турнира — `AetherhubTimedImportJob`
- **Когда:** `run_repeating` каждые 60 секунд.
- **Что делает:** импортирует турниры, у которых `aetherhub_import_time` == текущее `ЧЧ:ММ` и статус ≠ `CLOSED`. Время выставляет админ кнопкой в карточке турнира. При новых раундах — уведомления об оппоненте.

### 4. Финальный реимпорт счёта — `AetherhubFinalReimportJob` (`FINAL_REIMPORT_TIME = 09:00`)
- **Когда:** `run_daily` в 09:00 (не в 6 утра — иначе анонс «сбор завершён» мог бы уйти слишком рано).
- **Что делает:** перезатягивает турниры, созданные за последние `FINAL_REIMPORT_WINDOW_DAYS` (2) дня, чтобы добрать **финальный счёт** матчей. На AetherHub per-match счёт появляется только ПОСЛЕ завершения турнира (страница меняет формат js → edinorog, см. [`aetherhub_formats.md`](aetherhub_formats.md)), поэтому импорт во время игры его не видит. После добора счёта проверяет завершённость и при необходимости шлёт анонс «сбор метагейма завершён» (см. ниже) — это типичный момент его срабатывания.

### 5. Авто-раскрытие колод — `AutoRevealDecksJob` (`REVEAL_DECKS_TIME = 22:00`)
- **Когда:** `run_daily` в 22:00.
- **Что делает:** снимает `decks_hidden` у незакрытых турниров, созданных сегодня (во время регистрации колоды скрыты, чтобы их не копировали). Затем шлёт **один** анонс владельцу в личку (`settings.OWNER_CHAT_ID`, НЕ в чат турнира — пока так и в debug, и в prod): «👁 Колоды раскрыты», счётчики участников и короткую мету (топ колод из `StatsService.get_tournament_meta`). Анонс best-effort: сбой отправки не роняет джобу; нет `OWNER_CHAT_ID` — пропускается.

## Событийные действия (внутри импорта)

### Уведомления об оппоненте на новом раунде
Срабатывают в `AetherhubImportJob` и `AetherhubTimedImportJob`, когда `import_tournament`
возвращает новые номера раундов (`result.new_round_numbers`). Каждому
само-зарегистрированному игроку, включившему opt-in «Уведомления об оппоненте» в
`/settings` (`notify_opponent_rounds`, по умолчанию ВЫКЛ), отправляется ЛС о его паре:
стол, оппонент, его колоды и винрейт из DataLens (best-effort). Реализация —
`bot/telegram/round_notify.py` + `bot/handlers/round_notify.py`. Рассылка уважает
allow-list `notify_allowed_ids`.

### Анонс «сбор метагейма завершён»
Срабатывает после импорта во всех трёх импорт-джобах (`AetherhubImportJob`,
`AetherhubTimedImportJob`, `AetherhubFinalReimportJob`) **и после записи колоды** (в Telegram-
обёртках регистрации/записи оппонента через `announce_completion_if_ready`) — тем же
`maybe_announce_meta_gather_completed()`. Анонсируем **только при всех условиях**:

- турнир **привязан к AetherHub** (`aetherhub_url`) — у отладочных/ручных турниров его нет,
  их завершённость по счёту неопределена;
- прошло **≥ `MIN_TOURNAMENT_DURATION` (3 ч)** с начала игры (`Tournament.started_at`, который
  проставляется при первом импорте раунда ≈ старт игры). Настоящий турнир короче не бывает,
  так что это отсекает преждевременный анонс, когда AetherHub уже отдал счёт раннего раунда;
- у всех не-бай матчей есть счёт (`AetherhubImportService.is_tournament_complete`);
- **у всех участников заполнена колода** (`_all_decks_filled`) — метагейм собран только когда
  ни у одного участника не пусто (неважно, сам записался или дописали через «запись оппонентов»).
  Поэтому анонс проверяется и после записи колоды — уходит сразу, как заполнена последняя.

Ночной `AetherhubFinalReimportJob` (09:00) — гарантированный бэкап по счёту: там >4 ч всегда, так
что если вечерние импорты почему-то не сработали, счёт добирается утром (но пока не заполнены все
колоды — анонс всё равно ждёт).

Шлёт анонс «🎉 Сбор метагейма завершён» **в чат клуба** (`tournament.chat_id`) **и владельцу**
в личку (`settings.OWNER_CHAT_ID`), дедуплицированно, одним сообщением-альбомом (график меты +
страницы стендингов, текст — подписью к первой картинке). В тексте: счётчики участников, игроки
**без поражений (X-0)** с колодами (`get_undefeated_players`) и **благодарность метаписцам** —
кто записал ≥2 колод (`get_deck_recorders`). Идемпотентность — флаг
`Tournament.completed_announced_at`, ставится **только если доставили хотя бы в один чат** (сбой
не «съедает» анонс — повторится при следующем импорте). После анонса турнир **автоматически
закрывается** (`close_tournament`, REGISTRATION → CLOSED; best-effort). Нет адресатов (ни чата
клуба, ни владельца) — пропускается.

К анонсу прикладываются **картинки** (`send_photo`, чтобы в чате было превью): **график
«Метагейм-срез»** (см. [`meta_chart.md`](meta_chart.md)) и **итоговые стендинги** (см.
[`standings.md`](standings.md), длинный список — несколько страниц). Стендинги прикладываются,
только если уже есть результаты (иначе `build_standings` вернёт пусто — уйдут текст + график).

Текст анонса — **отдельным гарантированным сообщением** (`send_message`), картинки следом
best-effort. Если текст упал — исключение пробрасывается, флаг не встаёт, анонс повторится.
Сбой картинки (в т.ч. если Telegram её отверг) уже доставленный анонс не роняет и не зацикливает.

**Идемпотентность:** флаг `completed_announced_at` **занимается до отправки** атомарным
`UPDATE ... WHERE completed_announced_at IS NULL` (`_reserve_announce`); если доставить не удалось
ни в один чат — бронь снимается (`_release_announce`) и анонс повторится на следующем импорте.
Раньше флаг ставился после отправки — и это давало дубли на следующее утро: между проверкой и
записью флага код несколько раз уходит в `await` (рисование картинок, отправка альбома), а сессия
у бота одна на поток (`SessionLocal` — `scoped_session`), так что соседняя задача успевала её
закрыть, ORM-объект турнира становился detached и запись флага уходила «в никуда».

Данные для картинок читаются в основном потоке, а рисование (~180 мс CPU) уносится в
`asyncio.to_thread` — иначе оно заморозило бы event loop всему боту. Сессию SQLAlchemy
в поток передавать нельзя, поэтому `prepare()` (БД) и рисование (чистый CPU) разделены;
общая безопасная обёртка — `bot/chart.py` (`build_chart`, `build_standings`).

### Ачивки после закрытия турнира

Сразу после закрытия турнира (шаг 4 в `maybe_announce_meta_gather_completed`) вызывается
`send_achievements_report()` — движок ачивок пересчитывает выдачи и прогресс всех участников и
шлёт **один агрегированный отчёт владельцу** (`settings.OWNER_CHAT_ID`). Подробности правил и
режимов — [`achievements.md`](achievements.md).

- Гейт: feature flag `achievements` (включён по умолчанию). Пока `achievementsPlayerDm` выключен,
  игрокам про ачивки не пишется ничего — адресат ровно один.

После штатного закрытия тот же шов может передать полный дейлик в Magic Oculus. Интеграция
включается feature flag `magicOculusImport` (по умолчанию включён), выполняется в worker thread
и использует отдельную DB-сессию. Перед POST сверяется число игроков с AetherHub, а journal
`magicoculus_imports` блокирует повторную отправку того же турнира или AetherHub URL. Сбой внешнего
API логируется, отправляется одним личным сообщением владельцу (`OWNER_CHAT_ID`) и не отменяет
закрытие турнира; автоматический retry намеренно отсутствует. В клубный чат и игрокам текст ошибки
не отправляется.
- Идемпотентность: значения счётчиков пересчитываются из первичных данных, выдачи защищены
  уникальным ключом `(user_id, code, level)`, отправленные помечаются `notified_at`. Повторный
  прогон турнира сообщений не шлёт.
- Best-effort: любое падение движка ловится и **не отменяет** уже доставленный анонс и закрытие
  турнира.

## Где менять

- **Дни/времена клубов:** команда `/schedule` в боте (данные в `club_schedules`) — НЕ код.
  Дефолты для сида пустой таблицы: `default_schedules()` в `core/clubs.py`.
- **Идентичность клуба (chat_id, AetherHub, эмодзи):** `club_identities()` в `core/clubs.py`.
- **Времена общих джоб:** константы `FINAL_REIMPORT_TIME`, `REVEAL_DECKS_TIME`,
  `FINAL_REIMPORT_WINDOW_DAYS` в `bot/scheduler.py`.
- **Регистрация джоб:** `setup_scheduler()` — там `run_daily` / `run_repeating`.
- **Таймзона:** `settings.TOURNAMENT_TIMEZONE`.

> Все джобы логируются (`logger.info`/`exception`) с префиксом имени джобы — искать
> в `journalctl` по `AetherhubFinalReimportJob`, `AutoRevealDecksJob` и т.п.
