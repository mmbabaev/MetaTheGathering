# Автоматические действия (scheduler)

Все автоматические действия по времени и событиям живут в `bot/scheduler.py`
(`setup_scheduler()`), которая регистрирует джобы в `app.job_queue` PTB. Времена
указаны в локальной таймзоне клуба (`Club.timezone`); если она не задана, используется
`settings.TOURNAMENT_TIMEZONE` (обычно Europe/Moscow).

Два типа автоматизации:
- **по времени** — `run_daily` / `run_repeating` (джобы ниже);
- **по событию** — действия, которые срабатывают внутри импорта при изменении
  данных (новые раунды → уведомления; см. раздел «Событийные действия»).

## Расписание клубов — живёт в БД (issue #124/#125)

⚠️ **Расписание — данные, а не код.** Строки лежат в таблице `club_schedules` и правятся
админом из `/schedule`. Правка в коде на прод НЕ влияет: код держит только дефолты для
первичного сида пустой таблицы (`core/clubs.py` → `default_schedules()`, засевается
`ScheduleService.ensure_defaults()` при старте бота).

Турнир создаётся в `create_time`: обычно в день игры, либо за `create_days_before` дней до неё.
Дата события в title/slug и текст анонса всегда относятся к игровому дню. Игра проходит в
`game_time`, импорт с AetherHub — в каждое из `import_times`, напоминание — в `reminder_time`.
Выключенная строка (`enabled=false`) не доходит до планировщика вообще: ни создания, ни
напоминания, ни импортов.

Дефолты для сида (актуальное состояние смотри в `/schedule`, а не здесь):

| Клуб | День игры | Создание | Игра | Напоминание | Импорты |
|------|-----------|----------|------|-------------|---------|
| 🐠 Goldfish | пятница | пятница 12:00 | 19:45 | 19:45 | 20:00–00:30 каждые 30 мин |
| 🦄 Edinorog | понедельник | понедельник 12:00 | 19:30 | 19:25 | 20:00–00:30 каждые 30 мин |
| 🦄 Edinorog | четверг | четверг 12:00 | 19:30 | 19:25 | 20:00–00:30 каждые 30 мин |
| 🎲🎲 Pair of dice | вторник | понедельник 18:30 | 19:30 | 19:25 | 20:00–00:30 каждые 30 мин |
| 🎲🎲 Pair of dice | воскресенье | суббота 18:30 | 13:30 | 13:25 | 14:00–18:30 каждые 30 мин |
| 🎲 Hobby Games | суббота | пятница 18:30 | 17:00 | 16:55 | 17:30–22:00 каждые 30 мин |

Время Hobby Games указано по Калининграду (`Europe/Kaliningrad`); для остальных клубов —
`Europe/Moscow`.

Отладочный клуб (`[DEBUG] 🐠`, четверг 12:30, импорт 12:31, `find_latest=True`) добавляется
только при `settings.DEBUG` и через БД **не** управляется — это свойство отладки.

`chat_id`, ссылка на AetherHub, город Magic Oculus, таймзона и эмодзи клуба — инфраструктура, остаются в коде
(`core/clubs.py` → `club_identities()`), из UI не меняются.

### Что можно править в UI

В карточке строки (`/schedule` → тап по строке):
- **🕐 Создание / 🎮 Игра / 🔔 Напоминание** — ввод времени текстом `ЧЧ:ММ`; для напоминания
  можно прислать «выкл», чтобы отключить (анонс 2 не шлётся).
- **🔄 Импорты** — пресет `начало-конец/шаг`, например `20:00-00:30/30` (каждые 30 мин с 20:00
  до 00:30, окно через полночь поддержано), или «выкл».
- **📆 День недели** — пикер из 7 дней. Смена на день, который у клуба уже занят, отклоняется
  (нарушение уникальности `(club_name, weekday)`).
- **⏸/▶️** — включить/выключить строку целиком.

Offset `create_days_before` пока не редактируется из UI: он задаётся миграцией расписания;
изменение дня недели или времени Pair of dice сохраняет создание накануне.

Добавление и удаление строк расписания через UI пока не делается — только правка существующих.

### Применение правок без рестарта

`reload_schedule_jobs(app)` снимает все джобы с префиксами `create_tournament[`,
`prestart_reminder[`, `aetherhub_import[` и вешает их заново по текущему состоянию БД.
Зовётся из `/schedule` после каждой правки, поэтому изменение действует сразу.
Глобальные джобы (таймер импорта, ночной реимпорт, авто-раскрытие колод) расписанием
не управляются и переживают перезагрузку без изменений.

## Джобы по времени

### 1. Создание турнира — `CreateTournamentJob`
- **Когда:** `run_daily` в `create_time` за `create_days_before` дней до игрового дня (по одной
  джобе на расписание). Для Pair of dice и Hobby Games регистрация открывается накануне в 18:30;
  для остальных клубов offset равен нулю.
- **Что делает:** если у клуба открыто меньше двух турниров, создаёт новый в статусе `REGISTRATION` и
  шлёт анонс с числом записавшихся и **кнопкой-диплинком «📝 Записать колоду»**
  (`send_registration_open`). Предыдущий турнир **не закрывается автоматически**: Goldfish может
  держать одновременно старый незавершённый и новый регистрационный турнир. Если открыты уже два,
  создание следующего пропускается до ручной проверки и закрытия одного из них. Плановые напоминания
  и импорт AetherHub выбирают самый новый открытый турнир; старый продолжает участвовать в финальном
  реимпорте по собственному ID/URL.
  Адресаты анонса регистрации — **групповой чат клуба** (`club.chat_id`, если задан) и владелец
  (`OWNER_CHAT_ID`), дедуплицированно. Диплинк `t.me/<bot>?start=deck_<id>` ведёт игрока сразу в
  запись колоды.
- Название: `<emoji> <Клуб> Pauper <дата игрового дня>`. Для созданного накануне турнира анонс
  говорит «завтра», а авто-раскрытие колод не срабатывает вечером перед событием.

### 1b. Напоминание перед стартом — `PreStartReminderJob`
- **Когда:** `run_daily` в `schedule.reminder_time` в день расписания (Goldfish 19:45, Edinorog 19:25). Регистрируется, только если у расписания задан `reminder_time`.
- **Что делает:** находит активный турнир клуба и шлёт напоминание «турнир начинается — запишите колоду» с той же кнопкой-диплинком (`send_registration_open`). После группового сообщения отдельно пишет в ЛС игрокам, которые явно зарегистрировались через «Укажу позже» и всё ещё не выбрали колоду. Нет активного турнира — молча пропускает.

### 1c. Обновление числа записавшихся — `RegistrationMessageRefreshJob`
- **Когда:** `run_repeating` каждые 60 секунд.
- **Что делает:** сравнивает реальное число участников с показанным в последних регистрационных сообщениях и редактирует только изменившиеся. Поэтому учитываются Telegram, web, CLI и импорты без специальных callback-хуков. Удалённые или недоступные сообщения отключаются после постоянной Telegram-ошибки; временные ошибки повторяются на следующем цикле.

### 1d. Сводка по колодам из ячейки — `CellarCoordinatorReminderJob`
- **Когда:** `run_repeating` каждые 60 секунд; доставка становится доступна за час до
  планового старта регистрационного турнира `Edinorog`.
- **Что делает:** собирает активные брони физических колод на дату турнира и отправляет каждому
  production-координатору из `CELLAR_COORDINATOR_USERNAMES` (или legacy
  `CELLAR_COORDINATOR_TG_IDS`) и владельцу отдельную сводку
  «имя → @username → колода»; в debug получатель только владелец. Успешная доставка
  фиксируется по паре `(дата, адресат)`, поэтому повторный цикл не дублирует сообщение, а временный
  сбой повторяется только для недоставленного координатора. Задача работает только при включённом
  `cellarDecks`; также действует `notify_allowed_ids`. Подробный flow: [`cellar.md`](cellar.md).

### 1e. Синхронизация каталога ячейки — `CellarCatalogSyncJob`

- **Когда:** каждое воскресенье в 23:00 по `Europe/Moscow`.
- **Что делает:** загружает публичную Google-таблицу ячейки в XLSX, обновляет физические копии,
  номера строк, ссылки и даты деклистов, примечания и доступность. Исчезнувшие строки не удаляет,
  а деактивирует для сохранения истории броней. Ошибка Google оставляет в работе последнюю
  успешную копию в БД; в Telegram ничего не рассылается. При выключенном `cellarDecks` источник
  не запрашивается.

### 2. Плановый импорт с AetherHub — `AetherhubImportJob`
- **Когда:** `run_daily` в каждое `aetherhub_fetch_time` (по джобе на каждое время). Если
  последовательность времён переходит через полночь (`23:30, 00:00, 00:30`), ночные джобы
  регистрируются на следующий календарный день.
- **Что делает:** находит Pauper-турнир игрового дня клуба на странице AetherHub
  (`find_todays_pauper_tournament`) → импортирует (`import_tournament`: участники, паринги,
  счёт) → сохраняет `aetherhub_url` турнира. После полуночи ищет событие за предыдущую дату.
  При новых раундах — уведомления об оппоненте (см. ниже).
- **Ручная кнопка `📥/🔄 AetherHub`:** использует тот же
  `find_todays_pauper_tournament` и дату игрового дня из `registration_close_at` в таймзоне клуба.
  Без точного совпадения даты старое событие не предлагается: бот сообщает, что турнир не найден,
  и даёт ссылку на Content Feed AetherHub-пользователя, привязанного к клубу, после чего по-прежнему можно
  прислать URL турнира вручную.

### 3. Поминутный импорт по флагу турнира — `AetherhubTimedImportJob`
- **Когда:** `run_repeating` каждые 60 секунд.
- **Что делает:** импортирует турниры, у которых `aetherhub_import_time` == текущее `ЧЧ:ММ` и статус ≠ `CLOSED`. Время выставляет админ кнопкой в карточке турнира. При новых раундах — уведомления об оппоненте.

### 4. Финальный реимпорт счёта — `AetherhubFinalReimportJob` (`09:00`, `12:00`, `18:00`)
- **Когда:** `run_daily` в 09:00 (не в 6 утра — иначе анонс «сбор завершён» мог бы уйти слишком рано).
- **Что делает:** перезатягивает активные, ещё не анонсированные турниры с URL, созданные за последние `FINAL_REIMPORT_WINDOW_DAYS` (2) дня, чтобы добрать **финальный счёт** матчей. После добора счёта проверяет завершённость и при необходимости шлёт анонс «сбор метагейма завершён». Ручное обновление AetherHub запускает ту же проверку завершения.

### 5. Авто-раскрытие колод — `AutoRevealDecksJob` (`REVEAL_DECKS_TIME = 22:00`)
- **Когда:** `run_daily` в 22:00.
- **Что делает:** снимает `decks_hidden` у незакрытых турниров, созданных сегодня (во время регистрации колоды скрыты, чтобы их не копировали). Затем шлёт **один** анонс владельцу в личку (`settings.OWNER_CHAT_ID`, НЕ в чат турнира — пока так и в debug, и в prod): «👁 Колоды раскрыты», счётчики участников и короткую мету (топ колод из `StatsService.get_tournament_meta`). Анонс best-effort: сбой отправки не роняет джобу; нет `OWNER_CHAT_ID` — пропускается.

### 6. Напоминания о незакрытых турнирах — `UnclosedTournamentReminderJob`
- **Когда:** ежедневно в `UNCLOSED_REMINDER_TIME` (10:00).
- **Что делает:** отправляет сообщение только владельцу (`OWNER_CHAT_ID`), если турнир остаётся незакрытым через 3 дня, и повторное напоминание через 7 дней. В сообщении — название, ID и заполненность колод. Успешная доставка фиксируется отдельными timestamp-полями турнира; при ошибке Telegram отметка не ставится и отправка повторяется на следующий день. Игрокам и в клубные чаты эта джоба ничего не отправляет.

### 7. Просьба заполнить недостающие колоды — `MissingDecksReminderJob`
- **Когда:** ежедневно в `MISSING_DECKS_REMINDER_TIME` (15:00 по `TOURNAMENT_TIMEZONE`). Единственное напоминание становится доступно в 15:00 на следующий календарный день после даты турнира (`registration_close_at`; для старых записей — `started_at` или `created_at`).
- **Что делает:** проверяет заполненность и, если хотя бы у одного участника не указана колода, отправляет в чат турнира шуточный вызов «мета-полиции» и список только игроков без колоды с их `@username`. При включённом `recordOpponents` сообщение поясняет, что помочь может каждый, а кнопка «Записать» открывает защищённый community-flow: участник без колоды сначала заполняет себя, остальные видят только незаполненных игроков; отдельная приписка выделяет незаполненных оппонентов текущего пользователя и номера раундов. Flow не меняет уже указанную колоду и сохраняет `deck_added_by_tg_id`; событие `meta_police_deck_recorded` содержит инициатора и целевого игрока. `message_id`, URL кнопки и исходный список пропусков сохраняются: после записи сообщение в чате редактируется, заполненные строки зачёркиваются, а после заполнения всех колод кнопка удаляется. В debug-боте владелец может воспроизвести live-flow кнопкой «🐞 Мета-полиция» в меню «Действия с турниром». Превью и все его обновления адресуются только в личку этого владельца; другие игроки и клубный чат сообщений не получают. При выключенном флаге остаётся прежняя кнопка «Записаться» без динамического tracking. Успешная доставка фиксируется в `missing_decks_reminder_1d_sent_at`; при ошибке Telegram или невозможности построить кнопку отметка не ставится и отправка повторяется на следующем ежедневном запуске. Если все колоды заполнены, сообщение не отправляется. Личных сообщений игрокам эта джоба не рассылает.

## Событийные действия (внутри импорта)

### Напоминание об отложенной колоде после второго раунда

В первые 7 часов после создания турнира игрок может зарегистрироваться без архетипа через
«Укажу позже». Это сохраняется отдельно от обычных импортированных/добавленных админом участников
без колоды. При первом импорте раунда 2 такому игроку, если колода всё ещё не выбрана, отправляется
ещё одно ЛС с кнопкой «Выбрать колоду». Срабатывает во всех вечерних путях импорта: автоматическом,
timed и ручном. Pre-start и round-2 напоминания имеют независимые отметки доставки; каждое успешно
доставляется не более одного раза. Получатели всегда фильтруются через `notify_allowed_ids`,
placeholder-пользователи с отрицательным `tg_id` исключены.

### Уведомления об оппоненте на новом раунде
Срабатывают в `AetherhubImportJob` и `AetherhubTimedImportJob`, когда `import_tournament`
возвращает новые номера раундов (`result.new_round_numbers`). Каждому
само-зарегистрированному игроку, включившему opt-in «Уведомления об оппоненте» в
`/settings` (`notify_opponent_rounds`, по умолчанию ВЫКЛ), отправляется ЛС о его паре:
стол, оппонент, его колоды и винрейт из DataLens (best-effort). Реализация —
`bot/telegram/round_notify.py` + `bot/handlers/round_notify.py`. Рассылка уважает
allow-list `notify_allowed_ids`.

### Анонс «сбор метагейма завершён»
Срабатывает после импорта во всех трёх импорт-джобах (`AetherhubImportJob`,
`AetherhubTimedImportJob`, `AetherhubFinalReimportJob`) **и после записи колоды** (в Telegram-
обёртках регистрации/записи оппонента через `announce_completion_if_ready`) — тем же
`maybe_announce_meta_gather_completed()`. Анонсируем **только при всех условиях**:

- турнир **привязан к AetherHub** (`aetherhub_url`) — у отладочных/ручных турниров его нет,
  их завершённость по счёту неопределена;
- прошло **≥ `MIN_TOURNAMENT_DURATION` (3 ч)** с начала игры (`Tournament.started_at`, который
  проставляется при первом импорте раунда ≈ старт игры). Настоящий турнир короче не бывает,
  так что это отсекает преждевременный анонс, когда AetherHub уже отдал счёт раннего раунда;
- у всех не-бай матчей есть счёт (`AetherhubImportService.is_tournament_complete`);
- **у всех участников заполнена колода** (`_all_decks_filled`) — метагейм собран только когда
  ни у одного участника не пусто (неважно, сам записался или дописали через «запись оппонентов»).
  Поэтому анонс проверяется и после записи колоды — уходит сразу, как заполнена последняя.

`AetherhubFinalReimportJob` (09:00/12:00/18:00) — повторный бэкап по счёту: там >3 ч всегда, так
что если вечерние импорты почему-то не сработали, счёт добирается утром (но пока не заполнены все
колоды — анонс всё равно ждёт).

Шлёт анонс «🎉 Сбор метагейма завершён» **в чат клуба** (`tournament.chat_id`) **и владельцу**
в личку (`settings.OWNER_CHAT_ID`), дедуплицированно, одним сообщением-альбомом (график меты +
страницы стендингов, текст — подписью к первой картинке). В тексте: счётчики участников, игроки
**без поражений (X-0)** с колодами (`get_undefeated_players`) и **благодарность метаписцам** —
кто записал ≥2 колод (`get_deck_recorders`). Идемпотентность — флаг
`Tournament.completed_announced_at`, ставится **только если доставили хотя бы в один чат** (сбой
не «съедает» анонс — повторится при следующем импорте). После анонса турнир **автоматически
закрывается** (`close_tournament`, REGISTRATION → CLOSED; best-effort). Нет адресатов (ни чата
клуба, ни владельца) — пропускается.

К анонсу прикладываются **картинки** (`send_photo`, чтобы в чате было превью): **график
«Метагейм-срез»** (см. [`meta_chart.md`](meta_chart.md)) и **итоговые стендинги** (см.
[`standings.md`](standings.md), длинный список — несколько страниц). Стендинги прикладываются,
только если уже есть результаты (иначе `build_standings` вернёт пусто — уйдут текст + график).

Текст анонса — **отдельным гарантированным сообщением** (`send_message`), картинки следом
best-effort. Если текст упал — исключение пробрасывается, флаг не встаёт, анонс повторится.
Сбой картинки (в т.ч. если Telegram её отверг) уже доставленный анонс не роняет и не зацикливает.

**Идемпотентность:** флаг `completed_announced_at` **занимается до отправки** атомарным
`UPDATE ... WHERE completed_announced_at IS NULL` (`_reserve_announce`); если доставить не удалось
ни в один чат — бронь снимается (`_release_announce`) и анонс повторится на следующем импорте.
Раньше флаг ставился после отправки — и это давало дубли на следующее утро: между проверкой и
записью флага код несколько раз уходит в `await` (рисование картинок, отправка альбома), а сессия
у бота одна на поток (`SessionLocal` — `scoped_session`), так что соседняя задача успевала её
закрыть, ORM-объект турнира становился detached и запись флага уходила «в никуда».

Данные для картинок читаются в основном потоке, а рисование (~180 мс CPU) уносится в
`asyncio.to_thread` — иначе оно заморозило бы event loop всему боту. Сессию SQLAlchemy
в поток передавать нельзя, поэтому `prepare()` (БД) и рисование (чистый CPU) разделены;
общая безопасная обёртка — `bot/chart.py` (`build_chart`, `build_standings`).

### Ачивки после закрытия турнира

Сразу после закрытия турнира (шаг 4 в `maybe_announce_meta_gather_completed`) вызывается
`send_achievements_report()` — движок ачивок пересчитывает выдачи и прогресс всех участников и
шлёт **один агрегированный отчёт владельцу** (`settings.OWNER_CHAT_ID`). Подробности правил и
режимов — [`achievements.md`](achievements.md).

- Гейт: feature flag `achievements` (включён по умолчанию). Пока `achievementsPlayerDm` выключен,
  игрокам про ачивки не пишется ничего — адресат ровно один.
- До Telegram-доставки непустой отчёт сохраняется в `logs/achievements/` как структурированный
  JSON для последующей read-only сверки с production DB. Сбой файлового лога не роняет анонс.
- Текстовые части дополнительно сохраняются в `achievement_report_deliveries` одной транзакцией с
  выдачами и прогрессом. При ошибке Telegram следующий запуск повторяет только недоставленные части.
- `achievement_processing_leases` сериализует расчёт и доставку одного турнира между процессами;
  lease освобождается в `finally`, а после аварийного завершения истекает автоматически.
- `achievement_processing_runs` хранит итог каждого завершённого расчёта. Если одно правило упало,
  остальные применяются, run получает `partial/failed`, а owner видит безопасное предупреждение.

После штатного закрытия тот же шов может передать полный дейлик в Magic Oculus. Интеграция
включается feature flag `magicOculusImport` (по умолчанию включён), выполняется в worker thread
и использует отдельную DB-сессию. Перед POST сверяется число игроков с AetherHub, а journal
`magicoculus_imports` блокирует повторную отправку того же турнира или AetherHub URL. Сбой внешнего
API логируется, отправляется одним личным сообщением владельцу (`OWNER_CHAT_ID`) и не отменяет
закрытие турнира; автоматический retry намеренно отсутствует. В клубный чат и игрокам текст ошибки
не отправляется. После успешного POST в клубный чат отправляется одно отдельное сообщение с прямой
ссылкой на публичную страницу турнира в Magic Oculus; личной рассылки игрокам нет.
Город выбирается из идентичности клуба: Goldfish/Edinorog → Москва, Pair of dice →
Санкт-Петербург. ID города и клуба затем разрешаются через актуальные справочники Magic Oculus.
- Идемпотентность: значения счётчиков пересчитываются из первичных данных, выдачи защищены
  уникальным ключом `(user_id, code, level)`, отправленные помечаются `notified_at`. Повторный
  прогон турнира сообщений не шлёт.
- Best-effort: любое падение движка ловится и **не отменяет** уже доставленный анонс и закрытие
  турнира.

## Где менять

- **Дни/времена клубов:** команда `/schedule` в боте (данные в `club_schedules`) — НЕ код.
  Дефолты для сида пустой таблицы: `default_schedules()` в `core/clubs.py`.
- **Идентичность клуба (chat_id, AetherHub, город Oculus, эмодзи):** `club_identities()` в `core/clubs.py`.
- **Времена общих джоб:** константы `FINAL_REIMPORT_TIMES`, `REVEAL_DECKS_TIME`,
  `FINAL_REIMPORT_WINDOW_DAYS` в `bot/scheduler.py`.
- **Регистрация джоб:** `setup_scheduler()` — там `run_daily` / `run_repeating`.
- **Таймзона:** `settings.TOURNAMENT_TIMEZONE`.

> Все джобы логируются (`logger.info`/`exception`) с префиксом имени джобы — искать
> в `journalctl` по `AetherhubFinalReimportJob`, `AutoRevealDecksJob` и т.п.
