# Внутренний Swiss-движок (beta)

Внутренний движок — отдельный beta-режим онлайн-турнира. Новые турниры `Endstep-ru`
и `Endstep draft` сразу создаются на `internal_swiss`; остальные турниры по умолчанию
работают через AetherHub. До первого раунда администратор может переключить обычный
онлайн-турнир на внутренний движок; после появления парингов режим зафиксирован.

Основа правил — [Magic Tournament Rules, 27 February 2026](https://media.wizards.com/ContentResources/WPN/MTG_MTR_2026_Feb27_EN.pdf),
разделы 3.1 и 10.2–10.4, приложения C и E.

## Жизненный цикл

1. У турнира обязательно задано время начала. Игроки записываются с обязательным архетипом,
   пока турнир находится в регистрации. После старта
   Swiss игрок может подтвердить дроп из меню выхода; дропнутый игрок не участвует в следующих раундах.
2. Администратор включает `🧪 Движок: Swiss` в дополнительных действиях турнира.
3. `🎲 Создать раунд 1` закрывает регистрацию, случайно фиксирует начальный порядок
   участников и объявляет рекомендуемое число раундов.
4. Игроки вводят и подтверждают результаты существующим двухшаговым интерфейсом.
5. Только после результата каждого не-bye матча появляется `➡️ Следующий раунд`.
6. После последнего раунда `🏁 Завершить Swiss` фиксирует `final_place` и закрывает
   турнир. В чат турнира отправляются финальные стендинги текстом, график меты и
   картинки итоговых стендингов. Итоговые данные совместимы с существующими экспортами
   и статистикой.

Администратор может дропнуть любого игрока через его меню действий. Внутри идущего Swiss
дроп сохраняется в турнире и не удаляет историю уже сыгранных матчей.

У `Endstep draft` отдельный запуск. Организатор сначала формирует случайную рассадку:
после этого вход и выход закрыты, но необязательный plain-text деклист всё ещё можно
загрузить. Затем отдельная кнопка запускает первый раунд. Для восьми мест первый раунд
сводит `1–5`, `2–6`, `3–7`, `4–8`; при другом размере используются две половины рассадки,
а последний нечётный игрок получает BYE. Дальнейшие раунды строятся обычным Swiss.

Если для клуба включена публикация парингов, каждый созданный внутренний раунд
отправляется в выбранный чат тем же путём, что импортированный раунд. Кнопка под
карточкой открывает турнир в личном чате с ботом; участник с незаписанным текущим
результатом сразу попадает в форму ввода счёта.

## Деклисты

- Записанный игрок может до начала турнира загрузить или заменить plain-text деклист.
  После старта он остаётся доступен игроку только для чтения.
- До закрытия турнира все деклисты видят только создатель турнира и владелец бота;
  обычные администраторы дополнительных прав не получают.
- После `CLOSED` кнопка «Статус» открывает список игроков, и любой пользователь может
  выбрать игрока и прочитать его деклист. Дропнутые участники остаются в списке.
- За 15 минут до планового начала новый внутренний Swiss один раз напоминает в личку
  реальным участникам без архетипа или деклиста. Миграция не включает такие напоминания
  для уже существующих турниров.
- В драфте архетип не нужен, деклист необязателен и напоминания о нём не отправляются.

## Раунды

Рекомендуемое число Swiss-раундов вычисляется из числа участников:
`max(3, ⌈log₂ N⌉)`. До первого раунда администратор может вручную задать число
Swiss-раундов (`⚙️ Настройки Swiss`) в диапазоне от 3 до 20. Число раундов
фиксируется до первого раунда и дальше не меняется. `Endstep draft` всегда играет
ровно **три раунда** без плей-оффа.

## Плей-офф

Для большого онлайн-турнира администратор может включить single-elimination плей-офф
(`⚙️ Настройки Swiss`): топ-8 или топ-16. Настройка делается до старта плей-оффа
и фиксируется после.

- Если активных участников меньше размера ката, плей-офф автоматически не играется:
  турнир завершается финишем по обычным Swiss-стендингам.
- Плей-офф добавляет `⌈log₂ size⌉` раундов: топ-8 → 3 (четвертьфинал, полуфинал,
  финал и матч за 3-е место), топ-16 → 4 (1/8 финала, четвертьфинал, полуфинал,
  финал и матч за 3-е место).
- Брекеты: топ-8 → `(1–8), (4–5), (2–7), (3–6)`; топ-16 → `(1–16), (8–9), (4–13),
  (5–12), (2–15), (7–10), (3–14), (6–11)`. Меньший seed ходит первым.
- Плей-офф-пары строятся по итоговым Swiss-стендингам; seed игрока не меняется
  после создания пар.
- Победа в плей-офф-матче обязательна: ничья в счёте 1–1 отклоняется при вводе
  результата.
- Итоговые места: 1–2 из финала, 3–4 из матча за 3-е место, выбывшие в одном раунде
  плей-оффа получают целые места по Swiss-месту перед катом, все остальные — по
  Swiss-порядку после ката.
- После старта плей-оффа дроп участника запрещён (раздельные рунд-пары уже
  зафиксированы).
- Стендинги не учитывают плей-офф-матчи: во время и после плей-оффа они показывают
  только Swiss-результаты; после `CLOSED` с сыгранным плей-оффом отображаются
  итоговые места.

## Паринги

- Первый раунд использует один случайный начальный порядок без алфавитного преимущества.
- Следующие раунды сначала минимизируют повторные встречи, затем разницу match points.
- Когда score group нечётный, один игрок получает pair-down, а его соперник — pair-up.
  При равных вариантах движок избегает повторного float в том же направлении и
  большого накопленного перекоса up/down.
- Для тестового размера до 18 игроков используется точная оптимизация: повторная
  встреча допустима только если без неё нельзя собрать полный раунд. Для более крупных
  beta-турниров применяется быстрая эвристика с дополнительным исправлением rematch.
- Столы упорядочены по текущему месту лучшего игрока пары.
- При нечётном числе участников BYE получает самый низкий в текущих стендингах игрок
  среди тех, у кого минимальное число предыдущих bye. Поэтому второй bye не выдаётся,
  пока его можно дать игроку без bye.

## Очки и стендинги

- Победа / ничья / поражение дают 3 / 1 / 0 match points.
- Дроп после сыгранного матча не отменяет его результат: очки обоих игроков и
  тай-брейки их оппонентов продолжают учитывать этот матч. Дропнутый игрок остаётся
  в промежуточных и финальных стендингах с пометкой `⛔ дроп`, но не попадает в новые
  паринги.
- BYE считается победой 2–0: 3 match points и 6 game points.
- Порядок тай-брейков: match points → OMW → GW → OGW.
- Match-win и game-win percentage каждого оппонента имеют официальный нижний порог
  33,3%. BYE исключается из OMW и OGW.
- Текущий UI хранит только победы в играх. Для счёта 1–1 движок считает третью
  незавершённую игру ничьёй, как предписывает Appendix C; для 0–0 это также не меняет
  результат ниже порога 33,3%.
- При полном равенстве официальных тай-брейков используется зафиксированный случайный
  начальный порядок, а не имя или Telegram ID.

В Telegram BYE виден и в парингах (`✅ без игры`), и в стендингах (`BYE ×N`).
Стендинги во время незаконченного раунда помечены как предварительные.

## Изоляция от AetherHub

- Значение по умолчанию — `aetherhub`; существующие турниры мигрируют именно в него.
- Кнопка AetherHub скрыта только у турнира с включённым внутренним режимом.
- Сервис импорта дополнительно отвергает попытку записать данные AetherHub во
  внутренний турнир, даже если вызвать старую callback-кнопку.
- Старый debug-симулятор остаётся доступен для внешнего режима и не участвует в
  настоящем Swiss-флоу.

## Ограничения beta

В этой версии нет no-show и пропусков:
следующий раунд создаётся только после заполнения всех результатов. Также пока нет
awarded byes. Плей-офф поддерживает только два фиксированных ката (8/16) без
повторных матчей. Для событий крупнее 18 игроков pairing
использует эвристику, а не полный перебор вариантов. Эти ограничения не меняют
обычный AetherHub-флоу.
