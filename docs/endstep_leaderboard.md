# Endstep Pauper RU leaderboard

Команда `/leaderboard` открывает выбор между `Moscow Pauper Ranked` и
`Endstep ru Pauper Ranked`. Вторая таблица пока owner-only и показывает игроков,
которые уже участвовали в турнирах `Endstep-ru` в MetaGatherer и указали Endstep-ник.

## Источник данных

Отдельный process `python -m workers.endstep_leaderboard` создаёт сессию через
штатный `Continue as Guest` и читает те же авторизованные JSON endpoints, которые
использует сайт. Логин, пароль и дополнительные environment settings не нужны.
Это внутренний first-party интерфейс сайта, а не опубликованный или гарантированно
стабильный публичный API.

Worker запускается отдельным systemd oneshot service: один раз после каждого deploy
и затем раз в сутки через persistent timer с небольшим случайным сдвигом. Успешный
результат добавляется в `endstep_ru_leaderboard_snapshots` одной транзакцией. История
снимков сохраняется; если Endstep или БД временно недоступны, новый снимок не создаётся
и бот продолжает показывать предыдущий успешный.

## Кто попадает в список

- реальный пользователь бота (`tg_id > 0`);
- хотя бы одно участие в турнире клуба `Endstep-ru`, независимо от состояния турнира;
- заполненный Endstep-ник;
- точное регистронезависимое совпадение ника в текущем Pauper leaderboard Endstep.

Участия в нескольких турнирах и варианты регистра в названии клуба не создают
дубликатов. Ники, которых нет в текущем лидерборде, выводятся владельцу отдельной
диагностической строкой и не получают RU-место. Если Endstep возвращает несколько
разных аккаунтов с одинаковым точным ником, ник отмечается как неоднозначный и тоже
не получает RU-место: бот не угадывает, какой аккаунт принадлежит игроку.

## Порядок и интерфейс

Сначала идут игроки с местом на сайте, в порядке Endstep rank. Provisional-игроки,
у которых сайт ещё не показывает rank, идут после них по убыванию rating. Номер
строки — место среди найденных RU-игроков; рядом показываются место на сайте,
rating, RD и W–L–D.

Список разбит на страницы по десять игроков. При открытии бот читает последний
успешный снимок только из локальной БД и показывает время его обновления по Москве.
Переход между страницами использует тот же снимок в `context.user_data`. Telegram
flow никогда не обращается к Endstep и не может запустить ручное обновление.

Обе кнопки выбора видны в приватном `/leaderboard`, но Endstep RU пока открывается
только владельцу. Никаких рассылок игрокам этот flow не делает.
