# Moscow Pauper Ranked

Рейтинг из [issue #306](https://github.com/mmbabaev/MetaTheGathering/issues/306) считается
на исторических и новых данных самого бота. Magic Oculus, DataLens и другие внешние API
источниками матчей не являются.

## Окно и eligibility

- начало: `2026-06-20 00:00` включительно;
- публичный рейтинг продолжается без сброса 20 сентября;
- админский `/ranked_preseason` остаётся фиксированным отчётом до `2026-09-20 00:00`;
- клубы: `Edinorog`, `Goldfish`;
- турнир должен быть закрыт;
- все его non-bye паринги должны иметь счёт;
- один AetherHub tournament ID учитывается один раз;
- bye не влияет на рейтинг;
- зеркальные строки `RoundPairing` превращаются в один матч;
- неоднозначный или противоречивый матч исключается и попадает в quality-report.

Дата турнира — `started_at`, а для старых строк без старта — `created_at`.

## Identity

Канонический игрок — `User.id`. Сопоставление имени игнорирует регистр, `ё/е`, порядок
имени и фамилии и точку после инициала. Один реальный Telegram-аккаунт и его одноимённые
placeholder-дубли автоматически объединяются во время импорта. Одна однобуквенная опечатка
допустима только тогда, когда внутри текущего турнира она однозначно ведёт к одному
зарегистрированному игроку с указанной колодой.

При объединении сохраняются ссылки из `Participant`, `RoundPairing` и `RoundMatch`.

## Формула

Алгоритм `glicko2-v1`:

- начальный rating `1500`;
- rating deviation `350`;
- volatility `0.06`;
- `tau = 0.5`;
- rating period — семь дней от начала preseason;
- победа / ничья / поражение = `1 / 0.5 / 0`;
- результаты `2:0` и `2:1` равны по весу.

Публичный score:

```text
Ranked Score = round(rating - 2 × RD + 0.5 × сыгранные матчи) - штрафы
```

Каждый реальный матч добавляет обоим игрокам `0.5` только в публичную проекцию. Bye и
несыгранные после drop раунды бонуса не дают. Скрытые `rating`, `RD`, `volatility` и будущие
Glicko-2 расчёты от бонуса не меняются. Прогноз в уведомлении показывает итоговое изменение
публичного Score, поэтому бонус участия уже включён в варианты win/draw/lose.

Игрок считается откалиброванным после минимум трёх турниров и десяти матчей. Это ограничение
использует диагностический top-10 в `/ranked_preseason`; публичный `/leaderboard` показывает
всех активировавшихся игроков, включая новых с начальным Score.

## Доступ

`/ranked_preseason` остаётся диагностической командой только для администраторов.
Публичный `/leaderboard` доступен всем в личном чате с ботом, показывает по десять игроков на
странице и содержит кнопки навигации, «Где я?» и «Правила».

Публичный рейтинг активирован по умолчанию feature flag `rankedPublic`. Игрок получает доступ
отдельным событием с источником `self_bot` или `cellar`. `self_bot` включает самостоятельную
регистрацию и самостоятельное указание своей колоды для уже импортированного участия;
самостоятельная бронь Cellar тоже считается активацией. Создание участия через `admin` или
`aetherhub_import` само по себе публичную видимость не даёт. Исторические записи автоматически
не открывают игроков: публичный список наполняется новыми самостоятельными действиями.

После активации:

- два подряд рейтинговых турнира без самостоятельного действия деактивируют игрока;
- каждая такая деактивация добавляет `50` штрафных очков только к публичному Score;
- скрытый Glicko-2 рейтинг и расчёты матчей штраф не меняет;
- пока игрок неактивен, новые пропуски не создают штрафы;
- `self_bot` или `cellar` возвращает игрока, обнуляет серию пропусков и начинает новый цикл;
- накопленные в сезоне штрафы после возвращения сохраняются.

Адресное уведомление об оппоненте показывает собственный Score. Для
активного публичного оппонента оно также показывает его Score и примерный прогноз изменения
при победе, ничьей и поражении. Для неактивного оппонента выводится только «Рейтинг соперника
скрыт»; его Score и прогноз не показываются, поскольку прогноз тоже раскрывает силу игрока.
Расчёт помечен как примерный: Glicko-2 применяет результаты недельными rating periods.

## Воспроизводимость

Рейтинг не создаёт таблицу с сохранёнными очками. Каждый вызов пересчитывает snapshot из
первичных данных бота; сохраняются только доказательства самостоятельной активации. Поэтому
одни и те же матчи и версия алгоритма дают один результат, а штраф нельзя случайно начислить
повторным импортом. В админском ответе указаны версия алгоритма и quality-счётчики включённых
и исключённых турниров и матчей.
