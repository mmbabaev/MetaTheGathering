# Колоды из ячейки

Issue [#260](https://github.com/mmbabaev/MetaTheGathering/issues/260) добавляет в Telegram-бот
эксклюзивную бронь физических колод клуба «Единорог» на ближайшие понедельники. Web UI сохранён
как дополнительный вариант того же сценария.

## Пользовательский flow

Весь flow закрыт feature flag `cellarDecks`, который по умолчанию выключен. Когда флаг включён,
игрок открывает в личке бота команду `/cellar` и проходит весь сценарий inline-кнопками, не выходя
из Telegram. При выключенном флаге команда и старые callback-кнопки отвечают, что функция
недоступна, web-маршруты возвращают 404, а фоновые задачи ячейки ничего не делают. Постоянная
ссылка убрана из общей web-навигации.

1. Пользователь выбирает одну из четырёх ближайших дат-понедельников.
2. Бот показывает каталог страницами по десять физических колод со статусами свободна, занята
   или недоступна. Активная бронь выбранной даты всегда стоит первой, за ней — до трёх последних
   уникальных физических колод из истории броней пользователя, затем остальной каталог. Карточка
   колоды содержит архетип, примечание, актуальность и кнопку деклиста, если ссылка есть в таблице.
3. Свободная физическая копия бронируется кнопкой «Забронировать». На одну дату у игрока может
   быть только одна активная бронь, а у физической копии — только один игрок. Свою бронь можно
   отменить после отдельного подтверждения.
4. О новой броне и отмене отправляется адресное личное уведомление только владельцу бота — и в
   production, и в debug. Ивану и Сергею сообщения на каждое действие не отправляются. В клубный
   чат эти сообщения также не отправляются.
5. Если турнир уже создан, выбранный архетип сразу ставится в запись игрока. Если турнира ещё
   нет, `CreateTournamentJob` переносит все брони даты в новый турнир до анонса регистрации.
6. Отмена возвращает прежний архетип игрока. Если участник был создан самой бронью, до старта
   турнира удаляется только эта автоматически созданная запись.

В меню дат остаётся кнопка «Открыть web-версию». Для неё бот создаёт персональную одноразовую
ссылку на 15 минут, которая авторизует Telegram-пользователя и переводит на `/cellar`; email
вводить не нужно. Telegram и web используют один каталог, ограничения и записи броней.

Диплинк `https://t.me/MetaGathererBot?start=cellar` открывает то же меню дат напрямую.
Production-координаторы из `CELLAR_COORDINATOR_TG_IDS` дополнительно видят в этом сообщении все
активные брони четырёх ближайших дат в формате `дата — имя — @username — физическая колода`.
Обычным игрокам этот список не показывается.

Конкурентная защита находится в БД: partial unique indexes запрещают две активные брони одной
копии или две активные колоды одного пользователя на одну дату. Поэтому две одновременные
операции бронирования не могут обе завершиться успешно.

## Каталог

Source of truth — публичная
[Google-таблица ячейки](https://docs.google.com/spreadsheets/d/1SJbffwDLqSFBg4assNJ0zPUIpObrIcY6VuY1otgt4lI/edit).
Она загружается в формате XLSX, чтобы вместе со значениями получить гиперссылки из названий.
Парсер читает:

- номер строки и колонку B — номер физической копии, название и ссылку на деклист;
- колонку C — дополнительную информацию;
- колонку D — дату актуальности листа.

Каждая колода показывается с номером строки таблицы (`Altar Tron · №13`), поэтому физические
копии одного архетипа не смешиваются. В метагейм при этом записывается чистое имя архетипа без
номера. Если у конкретной строки есть гиперссылка, пользователь видит кнопку «Деклист и
сайдборд». Строки с пометкой `дома` или `занято` недоступны и в Telegram-, и в web-каталоге.
Старые календарные столбцы таблицы не импортируются: новые эксклюзивные брони хранятся в
MetaGatherer.

`cellar_decks` хранит локальную проекцию таблицы: стабильный `source_key`, отображаемое и
мета-имя, номер строки, ссылку и дату деклиста, примечание, доступность и признак присутствия в
источнике. `CellarCatalogSyncJob` обновляет её раз в неделю, в воскресенье в 23:00 по
`Europe/Moscow`. Открытие Telegram- или web-каталога не обращается к Google. При первом запуске
пустая БД заполняется сразу; последующие рестарты вне воскресного окна не вызывают лишнюю
синхронизацию.
Исчезнувшие строки деактивируются, но не удаляются, чтобы сохранить историю броней. При временной
ошибке Google используется последняя успешная копия; встроенный список из #260 остаётся только
fallback для совершенно пустой БД.

## Уведомления координаторам

При включённом `cellarDecks` `CellarCoordinatorReminderJob` раз в минуту ищет турнир «Единорога»,
до старта которого осталось не больше часа. В production одну сводку в формате
`имя — @username — физическая колода` получают все ID из `CELLAR_COORDINATOR_TG_IDS` и владелец;
в debug — только владелец. Доставка идемпотентна по `(event_date, recipient_tg_id)`; временная
ошибка повторяется только для недоставленного адресата. Защитный `notify_allowed_ids` применяется
в обоих окружениях.

Это не массовая рассылка: список закрытый и настраивается только в env. Пример значения без
реальных идентификаторов:

```env
CELLAR_COORDINATOR_TG_IDS=<coordinator_1_tg_id>,<coordinator_2_tg_id>
```

## Основные файлы

- `services/cellar_sheet.py` — загрузка и разбор Google Sheets;
- `services/cellar.py` — синхронизация, бронь, отмена, интеграция с турниром и форматирование;
- `bot/telegram/cellar.py`, `bot/handlers/cellar.py`, `bot/keyboards/__init__.py` — Telegram-flow
  выбора даты, просмотра колод, бронирования и отмены, а также персональный web-вход;
- `web/routes/cellar.py`, `web/templates/cellar.html` — web flow;
- `bot/scheduler.py` — еженедельная синхронизация, привязка при создании турнира и адресная сводка;
- `core/models.py` — каталог, брони и журнал доставок координаторам.
