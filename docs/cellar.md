# Колоды из ячейки

Issue [#260](https://github.com/mmbabaev/MetaTheGathering/issues/260) добавляет в web UI
эксклюзивную бронь физических колод клуба «Единорог» на ближайшие понедельники.

## Пользовательский flow

1. Авторизованный пользователь открывает `/cellar` и выбирает одну из четырёх ближайших
   дат-понедельников.
2. Свободная физическая копия бронируется кнопкой «Хочу эту колоду». На одну дату у игрока
   может быть только одна активная бронь, а у физической копии — только один игрок.
3. В чат «Единорога» отправляется один анонс о новой брони. Отмена освобождает копию и также
   отмечается в чате.
4. Если турнир уже создан, выбранный архетип сразу ставится в запись игрока. Если турнира ещё
   нет, `CreateTournamentJob` переносит все брони даты в новый турнир до анонса регистрации.
5. Отмена возвращает прежний архетип игрока. Если участник был создан самой бронью, до старта
   турнира удаляется только эта автоматически созданная запись.

Конкурентная защита находится в БД: partial unique indexes запрещают две активные брони одной
копии или две активные колоды одного пользователя на одну дату. Поэтому два одновременных POST
не могут оба завершиться успешно.

## Каталог

Source of truth — публичная
[Google-таблица ячейки](https://docs.google.com/spreadsheets/d/1SJbffwDLqSFBg4assNJ0zPUIpObrIcY6VuY1otgt4lI/edit).
Она загружается в формате XLSX, чтобы вместе со значениями получить гиперссылки из названий.
Парсер читает:

- колонку B — название физической копии и ссылку на деклист;
- колонку C — дополнительную информацию;
- колонку D — дату актуальности листа.

Повторяющиеся названия — отдельные физические копии. Строки с пометкой `дома` или `занято`
показываются в web-каталоге как недоступные. Старые календарные столбцы таблицы не импортируются:
новые эксклюзивные брони хранятся в MetaGatherer.

`cellar_decks` хранит локальную проекцию таблицы: стабильный `source_key`, отображаемое и
мета-имя, ссылку и дату деклиста, примечание, доступность и признак присутствия в источнике.
Синхронизация выполняется при старте бота и при открытии `/cellar`, если последняя успешная
загрузка была более 15 минут назад. Исчезнувшие строки деактивируются, но не удаляются, чтобы
сохранить историю броней. При временной ошибке Google используется последняя успешная копия;
встроенный список из #260 остаётся только fallback для совершенно пустой БД.

## Уведомления координаторам

`CellarCoordinatorReminderJob` раз в минуту ищет турнир «Единорога», до старта которого осталось
не больше 15 минут. Каждому ID из `CELLAR_COORDINATOR_TG_IDS` отправляется отдельная сводка
«колода → игрок». Доставка идемпотентна по `(event_date, recipient_tg_id)`; временная ошибка
повторяется только для недоставленного адресата. В debug каждый личный адресат дополнительно
проверяется через `notify_allowed_ids`.

Это не массовая рассылка: список закрытый и настраивается только в env. Пример значения без
реальных идентификаторов:

```env
CELLAR_COORDINATOR_TG_IDS=<coordinator_1_tg_id>,<coordinator_2_tg_id>
```

## Основные файлы

- `services/cellar_sheet.py` — загрузка и разбор Google Sheets;
- `services/cellar.py` — синхронизация, бронь, отмена, интеграция с турниром и форматирование;
- `web/routes/cellar.py`, `web/templates/cellar.html` — web flow;
- `bot/scheduler.py` — привязка при создании турнира и адресная сводка;
- `core/models.py` — каталог, брони и журнал доставок координаторам.
