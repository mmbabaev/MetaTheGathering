# Принятые правила классификации

Обновлять этот файл только после явного решения владельца или подтверждённого турнирного кейса.

## Три уровня

1. `Archetype.name` — существующий публичный архетип либо исходный custom-ввод.
2. `general_name` — канонический конкретный тип колоды для общей статистики.
3. `macro_name` — более крупная стратегическая семья для экспериментального анализа.

## Канонические названия

- Двухцветные гильдии переводить в буквенные коды: Golgari→BG, Orzhov→WB, Izzet→UR, Rakdos→BR, Selesnya→WG. Парсер поддерживает все десять гильдий.
- Любой Gardens, включая `Golgari gardens`, `golgary gardens` и голый `Gardens`, считать `BG Gardens`: цветовых вариантов Gardens нет.
- `Affinity` имеет приоритет независимо от цвета и других слов.
- `Tron` имеет приоритет независимо от цвета и подтипа; конкретный `general_name` может сохранять Flicker/Altar/Monster/5C Tron, но `macro_name` всегда Tron.

## Крупные архетипы

- `BG Gardens` и `BG Pestilence` → `BG Control`.
- `Burn`, `Mono Red`, `Red Madness`, `Red Rally`, `Red Burn`, `BR Madness` → `Burn`.
- `Blue Terror` и `UB Terror` → `Terror`.
- `Blue Faeries` и `UB Faeries` → `Faeries`; `UR Faeries` пока не объединять сюда.
- Любой `* Affinity` → `Affinity`.
- Любой `* Tron` → `Tron`.

## Fuzzy-сопоставление

- Применять только к свободному/custom-вводу; программное создание справочника не сливать автоматически.
- Сначала использовать однозначное совпадение `general_name`, чтобы безопасно узнавать короткие специальные имена и синонимы.
- Затем сравнивать нормализованное имя с публичными архетипами и их алиасами.
- Минимальное сходство: `0.86`; минимальный отрыв от второго кандидата: `0.04`.
- Не использовать существующие custom-опечатки как эталон.
- Для слова Affinity в канонизаторе допустимы две редакционные ошибки; для короткого Tron — одна ошибка или перестановка соседних букв.
- При неоднозначности не угадывать: оставить новый custom-архетип и вынести кейс владельцу.

## Видимость

Экспериментальный `macro_name` показывать только owner в существующей финальной отбивке. Не добавлять его в клубное сообщение и не создавать отдельные уведомления игрокам.
